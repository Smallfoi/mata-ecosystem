# МАТА Ecosystem — правила работы (Claude)

Это монорепо экосистемы **МАТА**. Над ним работают **Claude** (единственный ИИ-агент,
решение владельца от 2026-08-14) и владелец проекта. Главное правило: **ничего не
теряется между сессиями, и ошибки не повторяются** — для этого ведутся журналы ниже.

> `AGENTS.md` — короткий указатель на этот файл (для инструментов, читающих эту
> конвенцию). Правила живут ТОЛЬКО здесь; синхронизировать ничего не нужно.

## Состав экосистемы
- `mata_kvartal/` — «Квартал», Flutter + Riverpod. Бег, захват территорий, баллы, клубы.
- `mata_store/` — SportStore, Flutter + Provider. Магазин.
- `САЙТ МАТА/` — сайт бренда (статика).
- `backend/` — ОБЩИЙ бэкенд: **Django 5 + DRF + PostgreSQL/PostGIS в Docker** (`backend/django_api/`). Единый аккаунт + общие баллы для всех.
- `ECOSYSTEM_API.md` — контракт API, единый источник правды по эндпоинтам для всех трёх продуктов.

Это не три отдельных продукта, а одна система: единый пользователь (SSO по телефону),
единый баланс баллов, общий backend. Баллы зарабатываются в Квартале (бег) и тратятся в Store.

## Единый источник правды о работе (ОБЯЗАТЕЛЬНО к ведению)
- **`docs/WORKLOG.md`** — журнал: *что сделано / что пробовали / что не вышло / что дальше*.
  Читать ПЕРЕД работой (хотя бы последние записи), дополнять ПОСЛЕ.
- **`docs/DECISIONS.md`** — принятые решения и их причины. Не переобсуждать без новой причины.
- **`docs/PITFALLS.md`** — грабли, тупиковые попытки, особенности окружения.
  **Не повторять то, что здесь уже записано как «не работает».**
- **`docs/MODULES.md`** — карта модулей экосистемы (что за модуль, где живёт, статус).
  Меняешь модуль — обнови его статус здесь.

## Перед началом работы
1. `git checkout main && git pull`.
2. Прочитать свежие записи `docs/WORKLOG.md` и весь `docs/PITFALLS.md`.
3. Проверить `git status` и текущую ветку.

## Во время работы
- `main` ЗАЩИЩЁН: прямой push запрещён. Работать в ветке: `feature/*`, `fix/*`, `docs/*`, `chore/*`.
- Все изменения — через **Pull Request**, CI должен быть **зелёным**
  (Flutter analyze/test для обоих приложений + проверка бэкенда).
- **Параллельные сессии Claude**: в основном чекауте `D:\MyProjectsCLAUDE` в один момент
  работает ОДНА сессия. Параллельной работе — отдельный `git worktree`. Перед каждым
  commit проверять `git branch --show-current`; в `git add` перечислять файлы явно,
  не `add -A`. (Реальный случай коллизии — PITFALLS «Две агент-сессии в одном чекауте».)
- Держать **контракты API стабильными** (особенно `auth` / `profile` / `loyalty`) — их используют все приложения.
- **Редактируемость контента (страж CI «CMS · Editable text»):** видимый КОНТЕНТ приложения
  (`mata_store`) должен идти через `RemoteText(...)` (владелец правит в Конструкторе). Новый
  `Text('кириллица')` мимо RemoteText валит сборку — либо обернуть в RemoteText (это контент),
  либо пометить `// staw-static` (служебный UI). Скрипт: `tools/check_editable_text.py`
  (baseline существующего — `tools/editable_text_baseline.txt`).
- **Дизайн/бренд/цвета/шрифты НЕ трогать** — пока ничего не утверждено (директива владельца).
  Сейчас важно одно: чтобы всё работало правильно, как экосистема, без багов. Красота — потом.
- Репозиторий **ПУБЛИЧНЫЙ**: никогда не коммитить секреты/PII (`.mcp.json`, `*.db` уже в `.gitignore`).
- Не двигать большие папки до согласования структуры монорепо.

## После работы
- Дополнить `docs/WORKLOG.md` записью: `## YYYY-MM-DD — Claude — заголовок` + блоки
  *Сделано / Пробовали — не вышло / Решения / Состояние / Дальше*. Новая запись — строго
  ПОД маркером `---` после шапки; при конфликте параллельных сессий в WORKLOG всегда
  сохранять ОБЕ записи (обе стороны конфликта), ничего не выбрасывать.
- Новое архитектурное решение → `docs/DECISIONS.md`. Новые грабли → `docs/PITFALLS.md`.
- Влить PR (squash). Убрать временные файлы.
- **Перед концом сессии всё должно быть на GitHub** (владелец работает с двух компьютеров,
  см. ниже): никаких незакоммиченных или незапушенных изменений. Незаконченное — в ветку
  `wip/<тема>` с push. Итог сессии — `git status` чистый, `git log origin/<ветка>..HEAD` пуст;
  если что-то осталось локально — прямо сказать владельцу, что и где.

## Два компьютера владельца: синхронизация только через GitHub
- **Стационарный ПК (Windows):** МАТА — `D:\MyProjectsCLAUDE`, Pareta — `D:\MyProjects\pareta`.
- **MacBook (в поездках):** оба проекта — клоны тех же репозиториев (`Smallfoi/mata-ecosystem`,
  `Smallfoi/pareta`).
- Единственный способ синхронизации — `git pull` в начале и `git push` в конце. Облачные
  папки (Dropbox/iCloud/OneDrive) для репозиториев не использовать — портят `.git`.
- Git НЕ переносит: секреты (`.env` — из Lockbox/менеджера паролей), локальные БД и кэши
  (поднимаются заново), память Claude (`~/.claude/.../memory` — на каждой машине своя; всё,
  что должно пережить смену компьютера, — в `docs/`).
- Перед работой над проектом с другой машины — `git pull` обязательно: другая сессия могла
  уже сделать задачу (8.11.2026 копию бэкапа Pareta вне сервера сделали на MacBook).

## Диски: НИЧЕГО не сохранять на C (директива владельца, 04.09.2026)
Диск C почти полон — всё рабочее и временное живёт на D:
- git worktree → `D:\mata-temp\wt\<имя>`; временные файлы/архивы → `D:\mata-temp\`.
- Кэши сборок: user-env уже выставлены `GRADLE_USER_HOME=D:\dev-cache\gradle`,
  `PUB_CACHE=D:\dev-cache\pub`, `TEMP`/`TMP=D:\mata-temp\tmp` — новые сессии подхватят.
  Сессии, запущенные ДО 04.09.2026, наследуют старый env — в командах сборки задавать
  `$env:GRADLE_USER_HOME` / `$env:PUB_CACHE` явно.
- Тяжёлые временные файлы (APK с телефона, ассеты, дампы) — только на D, и **удалять
  сразу после использования**: четверть гигабайта «на посмотреть» копится у каждой сессии.
- Отработанный worktree сносить немедленно (`Remove-Item -LiteralPath "\\?\<путь>" -Recurse`
  против длинных путей, затем `git worktree prune`).

## Окружение и команды (важное)
- ОС: Windows. Оболочки: PowerShell (основная) и git-bash. **Кириллица в PowerShell бьётся** —
  UTF-8-тексты писать через файловый инструмент или Python, не через PowerShell heredoc.
- Бэкенд (Docker): `cd backend && docker compose up -d` (db postgis + web Django на :8000).
  После перезагрузки сначала запустить Docker Desktop. Docker в dev иногда сам останавливается —
  **проверяй `GET /v1/health` перед тестами**, при падении перезапусти `docker compose up -d`.
- Телефон ↔ бек: `adb reverse tcp:8000 tcp:8000` (по USB). На улице связи с dev-беком нет —
  начисления уходят в офлайн-очередь и долетают при возвращении.
- GitHub: репозиторий **`Smallfoi/mata-ecosystem`** (public). `gh` лежит по
  `C:\Program Files\GitHub CLI\gh.exe` (в PATH появляется после перезапуска терминала).
