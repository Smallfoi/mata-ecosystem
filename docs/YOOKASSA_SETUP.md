# Подключение ЮKassa — пошагово

Всё на **ИП Татаринова Алена Анатольевна** (ОГРНИП 325140000028101, ИНН 143524274080) —
D-100. Другого имени в кабинете, договорах и документах быть не должно.

Код к включению готов: платёж создаётся, покупатель уходит на оплату, подтверждение
приходит вебхуком, возвраты (в том числе частями) работают, состав чека собирается.
Менять в коде ничего не нужно — оплата включается ключами (D-13, D-72, D-73).

## Что делает владелец

### 1. Магазин в ЮKassa

Регистрация на ИП Татаринову А.А. Понадобятся: ОГРНИП/ИНН, расчётный счёт ИП, адрес
сайта `mata-club.ru`, описание товара (спортивная одежда и обувь).

> **ОКВЭД.** Для интернет-торговли нужен **47.91.2**. Его пока нет — ЮKassa на модерации
> может из-за этого отказать. Заявление Р24001 подаётся бесплатно, через сайт ФНС или
> Госуслуги, срок 5 рабочих дней.

### 2. Настройки в кабинете ЮKassa

- **Способ оплаты: только СБП.** Решение владельца (D-71, D-72) — карты и кошельки не
  подключаем. В коде способ жёстко задан, в кабинете он должен быть включён.
- **Адрес для уведомлений (HTTP-notification):**
  `https://api.mata-club.ru/v1/payments/webhook`
  События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
- **Секретный ключ** — выпустить в разделе «Интеграция → Ключи API». Ключ показывается
  один раз, сохранить сразу.

Уведомлению мы не верим на слово: по нему берём только номер платежа и перезапрашиваем
статус у ЮKassa своими ключами. Подделать «оплату» подставным запросом нельзя.

> **Про адрес возврата.** Он почти не влияет на покупателя: сайт открывает оплату в
> отдельной вкладке, а в своей каждые 3 секунды сам спрашивает статус заказа и показывает
> «оплачено» без всякого возврата. Адрес нужен ЮKassa как обязательное поле и как место,
> куда упадёт вкладка оплаты (на телефоне — приложение банка). Поэтому ведём на главную.
> Отдельная страница «спасибо за заказ» со статусом — улучшение на потом.

### 3. Ключи в Lockbox

В секрет `mata-prod-secrets` (Yandex Lockbox) добавить четыре значения:

| Ключ | Значение |
|---|---|
| `PAYMENT_PROVIDER` | `yookassa` |
| `YOOKASSA_SHOP_ID` | shopId из кабинета |
| `YOOKASSA_SECRET_KEY` | секретный ключ из кабинета |
| `YOOKASSA_RETURN_URL` | `https://mata-club.ru/` — сюда покупатель вернётся после оплаты |

### 4. Чеки 54-ФЗ — «Чеки от ЮKassa»

Касса покупается не всегда: у ЮKassa есть свой сервис — **Настройки → Чеки от ЮKassa**.
Он сам отправляет чек в налоговую и покупателю, без регистрации кассы в ФНС, замены
фискального накопителя и договора с ОФД. У нас он **подключён** (24.09.2026).

Чтобы чеки действительно пробивались, наш сервер должен передавать состав чека вместе с
платежом. Это включается ещё одной записью в том же секрете:

| Ключ | Значение |
|---|---|
| `PAYMENT_RECEIPT` | `1` |

Система налогообложения — **УСН «доходы», без НДС** (подтверждено владельцем 25.09.2026).
Это значения по умолчанию (`tax_system_code=2`, `vat_code=1`), задавать ничего не нужно.
Другая система — тогда `PAYMENT_TAX_SYSTEM` и `PAYMENT_VAT_CODE`.

Чек уходит на телефон или email покупателя из оформления заказа — хотя бы одно из двух
обязательно, иначе касса чек не примет.

### 5. Применить на проде

Из **YC Cloud Shell** (прямой SSH режет провайдер, см. PITFALLS):

```bash
sudo bash /opt/mata/backend/deploy/refresh-env.sh
```

Скрипт пересобирает `.env` из Lockbox, проверяет обязательные ключи и перезапускает
`web/worker/beat`. Если Lockbox не отдал секреты — старый `.env` остаётся нетронутым.

## Как проверяем, что включилось

```bash
docker compose exec web python manage.py check_launch_readiness
```

Строка «Оплата заказов» должна стать `ready`. Дальше — живая проверка:

1. Заказ на маленькую сумму со своего телефона → приходит ссылка/СБП-форма.
2. Оплатили → заказ становится «оплачен» сам, вебхуком, без нашего вмешательства.
3. Возврат из админки → деньги возвращаются, баллы возвращаются на счёт.

Тестовая оплата 1С-разработчика (D-97) при этом продолжает работать отдельно: право
«оплатить без денег» выдаётся конкретному аккаунту и снимается галочкой.

## Что ещё держит боевые продажи

Касса больше не держит — «Чеки от ЮKassa» подключены. Осталось два пункта, и они
касаются только ЧАСТИ товара:

- **«Честный знак».** Одежда (6101–6117), верхняя одежда (6201–6217) и обувь (6401–6405)
  маркируются обязательно. Без кода маркировки в позиции касса чек не примет — значит
  продать их не получится. Место под код в заказе готово (`markCode`), сами коды выдаёт
  «Честный знак» после регистрации. **Немаркированное** (гели, салфетки, аксессуары)
  продаётся уже сейчас.
- **ОКВЭД 47.91.2** — для интернет-торговли, заявление Р24001, бесплатно.

Порядок: ОКВЭД → «Честный знак» → открываем продажи одежды и обуви. Немаркированный
товар можно продавать, не дожидаясь маркировки.
