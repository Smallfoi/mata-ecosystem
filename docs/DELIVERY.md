# Доставка МАТА — как подключаем службы

Живой план. Решение об очерёдности — D-93, отсрочка служб — D-92.
Обновлено 23.09.2026.

## Сейчас (на запуск)

**Доставка по Якутску своими силами.** Курьера заказывают вручную — Яндекс Доставка,
inDrive или свой человек. Магазин об этом знает ровно одно: покупатель указал адрес,
а дальше с ним связываются. Стоимость доставки в оплату **не входит** — в чеке ноль.

В админке заказа есть действие **«🚚 Передан курьеру»**: пишем, кто везёт и когда, —
покупатель получает уведомление («Курьер Яндекса, привезёт сегодня до 18:00»), заказ
переходит в «Отправлен». Текст хранится в заказе (`Order.courier_note`), видно в списке.

Открытый вопрос к владельцу: **кто платит за курьера** и показывать ли цену доставки
покупателю. Пока — ноль и договорённость голосом.

## Порядок подключения (D-93)

1. **Свой курьер** — сделано.
2. **Яндекс Доставка (город)** — первая внешняя интеграция, когда заказов станет
   больше, чем успевает свой курьер.
3. **СДЭК** — межгород и пункты выдачи.
4. **Почта России** — куда не возит СДЭК; по Якутии это заметная часть.
5. **inDrive** — переговоры параллельно; подключаем, если условия лучше Яндекса.

Порядок можно менять: витрина не знает, кто везёт (см. «слой перевозчика» ниже).

## Что нужно от владельца

| Служба | Что получить |
|---|---|
| Яндекс Доставка | кабинет для бизнеса + договор/счёт. Есть бесплатный демо-режим кабинета — посмотреть тарифы по Якутску |
| СДЭК | договор → в кабинете выдают `Account` и `Secure password` (это и есть ключи API). Вопросы — integrator@cdek.ru с номером договора |
| Почта России | договор + кабинет «Отправка» + **аванс на счёт**; два ключа: токен приложения и ключ пользователя |
| inDrive | публичного API для России нет — нужен прямой разговор (компания якутская) |

## Слой перевозчика (как строим, чтобы не переписывать)

Один интерфейс, много поставщиков: **посчитать → создать → трек → статус → отменить**.
Витрина и админка работают с интерфейсом, службы — сменные реализации.

- **Расчёт цены** считает бэкенд, не приложение: тарифы меняются, в телефоне их держать нельзя.
- **Пункты выдачи** — отдельный экран с картой; по объёму сопоставим с самой интеграцией.
- **Создание отправления** — кнопкой в заказе, не автоматом при оплате: сначала собрали.
- **Статусы**: СДЭК и Яндекс шлют вебхуки сами, Почту опрашиваем по расписанию.

## Чем это заблокировано

- **Вес и габариты товаров** — пусто у всех 3373 позиций. Без них тариф не посчитать
  (все службы считают по весу и объёму). Поля есть (D-79), заполняет 1С. Главный стопор.
- **Оплата** — доставка складывается с товарами в чеке, значит сначала ЮKassa.
- Адреса для Почты нужны разобранные и с индексом — у них своя нормализация.

## Альтернатива, которую стоит взвесить

Агрегатор (Яндекс Доставка умеет и это) — одна интеграция вместо трёх, сами разбираются
со СДЭК, Почтой и курьерами. Дороже за отправление, дешевле по работе и поддержке.
На десятках отправлений в месяц почти наверняка выгоднее.
