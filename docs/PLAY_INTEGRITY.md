# Проверка подлинности приложения Квартал (Play Integrity) — D-129

## Что это и зачем

Баллы за бег считает сервер, но цифры пробежки присылает телефон. Человек может
пересобрать приложение или запустить его на эмуляторе и присылать выдуманные
пробежки. Google Play Integrity — сервис Google, который на каждую отправку
пробежки отвечает:

- запрос пришёл из **нашего** приложения (подпись, имя пакета), а не из пересобранного;
- телефон **настоящий**: не эмулятор и не взломанная прошивка (root);
- цифры пробежки **не подменили** после выпуска токена: в токен вшит отпечаток пробежки.

**Режим сейчас — «наблюдение».** Проверка ничего не блокирует и баллы не меняет:
вердикт записывается и виден модератору в админке («Бег и модерация →
Подлинность приложения»). Решение об ужесточении принимаем потом, по реальным
данным.

## Что уже сделано (код в main)

- Квартал (Android) перед отправкой пробежки просит у Google Play токен
  (официальная библиотека `com.google.android.play:integrity`). Нет настройки,
  нет Google Play, нет сети — пробежка уходит без токена, как раньше.
- Сервер сохраняет токен, в фоне отдаёт его Google и записывает итог:
  «Подлинное», «Есть признаки подделки» (с причиной), «Не удалось проверить»,
  «Без токена (старая сборка)», «Платформа пока не проверяется» (iOS).
- iOS (App Attest) — место в протоколе есть, проверка появится после аккаунта
  Apple Developer.

Без ключей проверка **полностью выключена** — ничего не записывается и не меняется.

## Что сделать владельцу (один раз, ~20 минут)

1. **Проект в Google Cloud.** Открыть https://console.cloud.google.com, войти
   Google-аккаунтом МАТА, создать проект (например, «mata-kvartal»). На главной
   странице проекта записать **номер проекта** (Project number — только цифры).
2. **Включить Play Integrity API.** В проекте: «APIs & Services → Library» → найти
   «Google Play Integrity API» → **Enable**.
3. **Сервис-аккаунт.** «IAM & Admin → Service accounts → Create service account»,
   имя `mata-integrity`, роли не нужны. Открыть его → «Keys → Add key → Create new
   key → JSON» — скачается файл с ключом. **Этот файл — секрет**, в чат и в
   репозиторий его не присылать.
4. **Ключ на сервер.** Закодировать файл в одну строку base64:
   - Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("ключ.json"))`
   - Mac: `base64 -i ключ.json | tr -d '\n'`

   На сервере дописать строку `PLAY_INTEGRITY_SA_KEY_B64=<эта строка>` в файл
   секретов `/root/mata-secrets.env` (`sudo nano /root/mata-secrets.env`) и выполнить
   `sudo bash /opt/mata/backend/deploy/refresh-env.sh`. Ту же запись добавить в
   Lockbox `mata-prod-secrets` — чтобы ключ пережил пересоздание сервера. Файл
   ключа после этого удалить с компьютера.
5. **Номер проекта в сборку.** GitHub → репозиторий → Settings → Secrets and
   variables → Actions → вкладка **Variables** → New repository variable:
   `PLAY_INTEGRITY_PROJECT` = номер проекта из п. 1 (это не секрет). Со следующей
   Android-сборки Квартал начнёт присылать токены.
6. **(Желательно) отпечаток нашей подписи** — чтобы ловить пересобранные копии
   приложения. Раздаём APK не через Google Play, поэтому Google не знает, какая
   подпись «наша»; сервер сравнит сам. Отпечаток SHA-256 ключа подписи
   (`keytool -list -v -keystore <файл keystore>`, строка SHA256) положить в секреты
   сервера как `PLAY_INTEGRITY_CERT_SHA256`. Могу посчитать его сам, если дадите
   доступ к keystore на время.

## Переключатели (секреты сервера, всё по умолчанию выключено)

| Имя | Что делает |
|---|---|
| `PLAY_INTEGRITY_SA_KEY_B64` | Ключ сервис-аккаунта. Без него проверка выключена. |
| `PLAY_INTEGRITY_PACKAGE` | Имя пакета, по умолчанию `ru.mata.kvartal`. |
| `PLAY_INTEGRITY_CERT_SHA256` | Наши отпечатки подписи (через запятую). Задан — чужая подпись = признак подделки. |
| `PLAY_INTEGRITY_FLAG_REVIEW` | `1` — при признаках подделки аккаунт уходит «на проверку» модератору (баллы за активность замораживаются, D-107). |
| `PLAY_INTEGRITY_REQUIRE_PLAY` | `1` — установка не из Google Play = признак подделки. Включать только когда раздача пойдёт через Play. |

## Что нельзя проверить без аккаунтов

Связь с Google целиком (выпуск токена на телефоне, ответ Google серверу) проверена
только на подставных ответах: живого проекта Google ещё нет. После шагов 1–5 нужна
одна живая проверка: поставить новую сборку, пробежать (или пройти) пару минут и
посмотреть запись в админке. Отдельно проверить, что Google выдаёт токены
приложению, которое раздаётся не через Google Play (по документации — выдаёт,
приложение будет «не опознано Play», и это ожидаемо).
