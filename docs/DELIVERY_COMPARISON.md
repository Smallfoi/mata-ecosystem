# Службы доставки из Якутска — подбор перед интеграцией

> 11.09.2026. Запрос владельца: список служб, с кем можно сделать интеграцию для **расчёта
> стоимости** и **передачи отправления**, и как это делается. Решение — позже. Условия служб
> меняются; перед подписанием договора перепроверить.

## Коротко

Для старта хватит **трёх прямых интеграций**:

- **СДЭК** — основная доставка по России (пункты выдачи и курьер), офис в Якутске;
- **Почта России** — туда, куда не доезжают остальные, вплоть до дальних сёл;
- **Яндекс Доставка** — экспресс-курьер по Якутску за час.

Не сейчас: агрегатор ApiShip (минимум 25 000 ₽/мес), Boxberry (вошла в Яндекс Доставку,
пункты не принимают новые посылки), Ozon Доставка (нужны те же товары на маркетплейсе Ozon
или эквайринг Ozon Pay), 5Post (в Якутске не нашёл).

## Как делается интеграция

**СДЭК** — REST API v2, OAuth2 (`client_credentials`), тестовая среда `api.edu.cdek.ru`,
документация api-docs.cdek.ru. Методы: `POST /v2/calculator/tarifflist` (цена и срок по
весу и габаритам), `GET /v2/deliverypoints` (пункты), `POST /v2/orders` (отправление),
статусы. Интеграция бесплатна.

**Почта России** — тарификатор `tariff.pochta.ru` (публичный, без договора); сервис
«Отправка» `otpravka.pochta.ru` (проверка адреса, индекс, отправление, ярлык, документы —
только по договору, тестовой среды нет); трекинг `tracking.pochta.ru`.

**Яндекс Доставка** — бизнес-кабинет, API-токен в профиле; предварительная оценка цены,
создание/подтверждение/отмена заявок, статусы. Адреса — только координатами (нужен перевод
адреса в точку). Тестирование — на реальных заказах.

**Через 1С** — есть готовые модули доставки (СДЭК для УТ 11.4.6+, универсальные на 40+
служб): отправление можно создавать из 1С после сборки.

## Как это ляжет на наш путь заказа (D-72)

1. **Оформление** — адрес или пункт выдачи; цену и срок считает **сервер** у служб, клиенту не верим.
2. **Оплата** — товары и доставка одним платежом по СБП, подтверждение ЮKassa.
3. **Передача службе** — после оплаты: отправление и трек-номер (сервер через API или 1С после сборки).
4. **Отслеживание** — статусы службы → уведомления покупателю.

## Что нужно до начала

- **Вес и габариты товаров.** Сейчас их нет ни в `catalog.Product`, ни в выгрузке из 1С —
  без них расчёт невозможен. Правильно — завести в 1С; временно — типовые размеры по категориям.
- **Договоры:** СДЭК, Почта России, Яндекс Доставка.
- **Адрес отправки** в Якутске.

## Решения владельца

- **Кто создаёт отправление:** сервер сразу после оплаты или 1С после сборки (склад знает точный вес упаковки).
- **Как оплачивается доставка:** по D-72 — вместе с заказом по СБП, службе платим мы по договору.
  Оплата службе при получении — наложенный платёж, D-72 его исключил. Владелец 10.09 упоминал
  «платят напрямую им» — сверить.

## Оценка работ (после договоров и весов)

| Работа | Дни |
|---|---|
| Вес и габариты в каталоге + приём из 1С | 1–2 |
| СДЭК: расчёт, пункты, отправление, статусы | 4–6 |
| Почта России: расчёт, «Отправка», трекинг | 3–5 |
| Яндекс Доставка по Якутску (+ адрес → координаты) | 2–3 |
| Выбор доставки и пункта в Store и на сайте | 4–6 |
| **Всё вместе** | **3–4 недели** |

Первыми разумно СДЭК и курьер по Якутску — около двух недель.
